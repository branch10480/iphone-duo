DuoLab — ヒンジ・2面レイアウト検証アプリのタブガイド

DuoLab は iPhone のヒンジ・2面（折りたたみ）フォームファクタを iOS 27.1 で検証するためのサンプルアプリ。 7 つのタブのそれぞれが、新しい API のどれをどの目的でデモしているかを、 SwiftUI と UIKit の両側からこの 1 ページでまとめる。

対象 DuoLab（iOS 27.1・ヒンジ対応 iPhone） 構成 7 タブ + Companion ウィンドウ 検証 iOS シミュレータ実測（2026-09-23）

概要

要点

  • 各タブは新しいヒンジ API を 1 つずつ実証するデモで、レイアウト判断（size class / Reserved Region）とインタラクション（Hinge）を役割分けて設計している。
  • Overview / Two Pane / Regions / Bar / Scenes は SwiftUI 側 API、UIKit タブが同じ機能を UIKit 側 API で実装。両側の実装差を比較できるのがこのアプリの狙い。
  • ヒンジの pose（閉じた外側 / 開いた内側）で表示が変わるのが前提なので、全タブが open / closed 両方で表示確認済み（2026-09-23 巡回、sim）。
  • 実機でしか観測できない 3 件（fold 別角度 / StandBy・アプリエクステンション / カメラ撮影・onAvailabilityChange）は残作業。

DuoLab は 1 画面に 7 タブを並べた TabView（DuoLab/DuoLabApp.swift）で構成される。

前提

本アプリはヒンジ対応 iPhone のシミュレータ / 実機で動く（@available(iOS 27.1, *)）。 従来の 1 画面 iPhone ではヒンジ関連 API が値を返さないため、Overview 以外の多くの値は — や no hinge になる。これは不具合でなく設計。

実装のポイント

  • size class で判断する — 実測（2026-09-21、sim）: 内側（open）= regular×regular → wide、外側（closed）= h-compact / v-regular（従来 iPhone portrait と同型）。ヒンジ pose の変化は orientation 変化として現れないため、orientation ではなく size class で分岐する。
  • UIScreen.main を使わない — 2 ディスプレイのデバイスでは「main」がどちらを指すか不確実なので、\.displayScale（traitCollection.displayScale）で取得する。
  • safe area は 4 辺独立 — 左右の inset が等しいと仮定せず T / R / B / L を個別に観測する。
  • orientation の報告値は毎 body で読み直す — @State + 通知の組み合わせは pose のみ変化（orientation 非変化）すると stale になるため、GeometryReader の再評価で読み直す。delegate で beginGeneratingDeviceOrientationNotifications() を有効化。
  • Concentricity — \.concentricCornerRadii で 4 角の半径を観測。丸いコンテナ内では追従半径を返す。

Hingeインタラクション

onHingeChange（SwiftUI）でヒンジの status / angle を観測し、それらをインタラクション・エフェクトに使うデモ。ヒンジデータでレイアウトを直接変えないのが設計の原則。

実装のポイント

// 2 引数（old, new）のシグネチャ
onHingeChange { _, context in
    hinge = context.hinge   // angle: 0 rad（閉）… π rad（開）
}
  • 半円ゲージ — ラジアンを 0…180° に正規化して Arc で描く。SwiftUI の Shape.path(in:) は親 frame 座標と一致せず描画がずれる（実スクショで弧の底がはみ出していた）ため、Canvas に置換して frame 領域をクリップし frame 局座標で描画する。2026-09-23 巡回で修正・目視確認済み。
  • Driven Effect — ヒンジ角度で明るさが変わる装飾。半開（live）のときだけ発光し、angle を駆動源にしたエフェクトの例。
  • status の比較 — SwiftUI DeviceHinge.Status は struct（closed / partiallyOpen / fullyOpen の static var、unknown なし）なので switch せず == 比較で判定する。unknown があるのは UIKit 側 UIHinge.Status（4 case enum、UIKit タブ参照）。

役割分担（このアプリの原則）

ヒンジデータ（status / angle）はインタラクション・エフェクト専用。レイアウト判断は Arrangement（Two Pane）と Reserved Regions（Regions）で行う。ヒンジ角度にレイアウトを直接紐づけると、半開角度の幅（DeviceHub では Book=128° のみ観測）で挙動が変わって制御不能になる。

// または .overlay.axes(.vertical)
  • auto 判定 — コンテナ高（safe area 済み、onGeometryChange で実測）が閾値 600pt 未満なら overlay、以上なら split。toolbar ボタンで手動指定も可能。
  • 実測の落とし穴 — 2026-09-22 実測: .split.axes(.vertical) はpane が収まらなければ secondary を非表示にする。video box（16:9）の理想高が 2 段 slot を超える landscape（867×553pt）で secondary が消滅していた → video box に高さ上限 200pt（pane の理想高を有界化）＋ コンテナ高で自動切替して解消済み。
  • zIndex 表示 — \.overlayArrangementZIndex を画面下隅に表示。overlay で折りたたまれると値が変化するため、live に追従していることを画面で確認できる。

Regionsレイアウト

reservedRegions で折り目（division）・カメラ（occlusion）の予約領域をクエリし、content を折り目を横断しないよう退避（displacement）配置するタブ。

デモの構成（pose 別）

occlusion（青枠）は右上に位置する（closed・外側と open・内側で幅が異なる）。division（赤破線）は closed では 0 件、open では inactive（幅 0）のため淡い表示。content 行は折り目を避けて左側へ退避（displacement）。

Content row 2

occlusion: x 82%〜100% / y 0〜25%（実測）

(inactive)

青枠 = occlusion（カメラ孔 = status bar の載る領域。実測: 右上に縦長 1 枠、2 件の境目に虚線）／ 赤破線 = division（折り目、中央を横断。closed=0件 / open=inactive）／ ピル = live summary

実装のポイント

let divisions = proxy.reservedRegions(kind: .division, options: includeInactive ? [.includeInactive] : [])
let occlusions = proxy.reservedRegions(kind: .occlusion, options: includeInactive ? [.includeInactive] : [])
let clear = foldClearRect(divisions: divisions, container: proxy.size)
// content は foldClearRect で広い側へ丸ごと移動（displacement）
  • displacement — 折り目バンドは表示領域の中央を横切り、方向は pose に依存する（縦 / 横）。content 全体を「折り目を横断しないクリア側」（広い側）の矩形に丸ごと配置し、行が折り目をまたがないようにする。
  • occlusion（カメラ孔）ラベル非表示化 — occlusion region は status bar（時刻・Wi-Fi）の載る領域そのもので、closed pose では件数 2 が右上に完全に接して 1 つの縦長枠に見える（2026-09-24 実測）ため枠内のどこに置いてもラベルが図形と被る。2026-09-23 巡回でラベルを非表示にし、枠線（青）と summary の数だけで可視化。division のラベルは status bar と被らないため枠内に出す。
  • inactive toggle — .includeInactive を切り替えて「折りたたまれていないとき inactive（幅 0）」になる挙動を確認する。
  • live summary — 下隅のピルが件数と active 数を常時表示（open = division 1（active 0） / occlusion 2（active 1）、closed = division 0 / occlusion 2（active 2））。
